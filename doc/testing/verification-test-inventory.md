# FieldDay Verification Test Inventory

Last updated: 2026-10-31

This is the repository copy of the team RVTM for the whole FieldDay repository. A status of **Partial** means the listed test has not completed every acceptance criterion; it does not mean its feature is absent. A requirement can be marked not run when its feature or test environment is not ready. Code described as implemented in an open PR becomes part of the release once that PR is merged through `dev` to `main`.

In the SDP, FR-9 is Session Attendance Confirmation and FR-10 is Friend Management. This table has used FR-9 for push notifications and FR-11 for friend requests, so the attendance rows added on 2026-10-31 are `TC-FR9-05` and later, with the SDP name in the Req. ID column.

The RVTM uses `TC-FR2-03` twice for different tests. This table names them `TC-FR2-03A` and `TC-FR2-03B` so both are traceable.

## CI plan

The build workflow runs lint, backend validation, the unit tests and the Expo exports on a fresh GitHub-hosted Ubuntu runner. The Backend test job starts a MongoDB 7 service container. It then starts the backend and runs `test:integration` and `test:chat` against it over HTTP. It also runs the authorization, profile setup, session membership, session visibility, session lifecycle, sport preferences, realtime, cooldown, attendance and accounts tests against the database. No repository secret or shared database is needed. Each test deletes the records it creates and exits with a failing code if an assertion fails.
